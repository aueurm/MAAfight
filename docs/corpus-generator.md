# v2 传统模式与语料先验

## 语料模型

`scripts/build-corpus-model.js` 将两个目录中的 200 份全歼作业编译为 `src/data/corpusPrior.v1.json`。产物只保存动作语法、相对点位和地图上下文统计，不保存作者、文档或完整作业。

```bash
npm run corpus:audit
npm run model:build
```

按关卡留一统计禁止同关作业成为生成捷径。

## 公开作业训练先验

`scripts/train-public-copilot.js` 将 PRTS Plus 多时间窗作业编译为 `src/data/copilotPrior.v1.json`。产物只保存同关 / 同上下文聚合特征，例如部署热力图、方向比例、前三次部署位置计数、动作比例和干员 / 技能使用计数，不保存完整动作序列。

```bash
node scripts/train-public-copilot.js --preset conservative --report
```

无网络或调试时可复用本地语料：

```bash
node scripts/train-public-copilot.js --reuse-corpus --input data/prts-plus-latest-100 --input data/prts-plus-2025-06-18-100 --report
```

首轮运行时只进入 `Scoring` 的弱排序分，不改候选展开；本地 killed / total 反馈仍在公开先验之后覆盖排序。

## 静态战斗数据

```bash
node scripts/build-operator-combat-model.js --game-data <excel-dir> --commit <upstream-commit>
```

推荐上游：[Kengxxiao/ArknightsGameData](https://github.com/Kengxxiao/ArknightsGameData)。当前可解析 commit 为 `b327f67a1d73fe9a2501f4e159603a30da75911f`。

构建目录必须同时包含 `character_table.json`、`skill_table.json`、`range_table.json`、`uniequip_table.json` 和 `battle_equip_table.json`。`--commit` 必须是完整 SHA。产物 `src/data/operatorCombat.v2.json` 记录五张表的 SHA-256，稳定排序且不含构建时间；运行时不读取完整 GameData，也不解析描述文本。

## 搜索

v2 从 `MapData` 直接构造候选，不调用旧分析器或旧脚本生成器：

1. 从完整模型目录按关卡需求和队伍剩余能力缺口扩展 `(operator, skill)`；先用宽度 4 得到完整队伍，再利用剩余时间扩大到默认宽度 32。显式配置更小宽度时保留该宽度。
2. 使用真实范围格、位置和朝向进行联合部署规划；同一队伍不重复构造候选。
3. 每个候选先通过部署、费用与路线硬约束，再按 15 秒窗口完成技能、治疗、控制和范围交集评分。
4. 目标搜索预算仍为 1200 ms，其中最多预留 50 ms 收尾。时间检查为协作式，单次计算可能越过截止时间；扩大搜索超时时可以返回已合法、已评分的候选，尚无此类候选时明确报错。

渐进搜索会改变预算内探索到的候选集合，不保证与旧宽度 32 一次展开得到相同作业；它没有放宽战术约束。

基础权重：局部交战 30%、点位 20%、费用时序 15%、语料 15%、功能覆盖 10%、自动化 10%。

搜索失败时直接报错，不生成 fallback。

## 战术构造约束

这些约束由 `CandidateBuilder.ts` 统一执行，只用于产生和排序候选；它们不是通关率模型。

### 选人和技能

- 玩家干员库只限制可用范围，不取消高强度干员与技能偏好。
- 已指定技能的干员只枚举指定技能；已确认会在结束后令自身或友方失能的技能不参与传统模式候选。
- 开局部署压力高时，第一槽和第一名部署者优先为先锋。偏好加分仍服从关卡能力缺口、费用和地图适配。
- `musha`、`reaper`、`unyield` 等无法接受友方治疗的分支默认降低入队优先级；只有其单守价值仍能覆盖队伍缺口时才会保留。

固定强度偏好如下。它是软排序，不是每关配额；未列技能的三个“全技能”干员允许 S1/S2/S3。

| 可用技能 | 干员 |
| --- | --- |
| S1 | 黍、逻各斯、纯烬艾雅法拉、塑心、阿斯卡纶、歌蕾蒂娅 |
| S2 | 凛御银灰、怒潮凛冬、乌尔比安、圣聆初雪、艾雅法拉、凯尔希·思衡托、遥 |
| S3 | 忍冬、玛恩纳、维什戴尔、荒芜拉普兰德 |
| S2/S3 | 赤刃明霄陈、司霆惊蛰、澄闪、Mon3tr、新约能天使、提丰 |
| 全技能 | 斩业星熊、塞雷娅、酒神 |

当前明确排除：阿米娅 S2/S3，以及幽灵鲨、雷蛇、远山、布洛卡、断罪者、极光、洛洛、苍苔的 S2，森蚺 S3、蚀清 S1。该表在战斗模型提供结构化“技能结束后失能”字段前与代码中的精确名单同步维护。

### 前线、Boss 和治疗

- 每个地面目标点优先分配一名长期站场近战；高压开局把前线限制在最深防区附近，先锋和快速复活不占最终目标前格。
- Boss 出生路线按 `enemyId -> routeIndex -> endPosition` 追到目标点。该目标的主阻挡优先使用可接受治疗的近战；禁疗干员优先单守其余普通支路，没有合法普通支路时才保留地图可行回退。
- 近战朝向优先面对来敌方向；多个方向相交时按路线敌方总威胁排序。
- 持续治疗者优先覆盖尚未覆盖的 Boss 主阻挡，再覆盖其余可治疗近战。禁疗干员不占用治疗覆盖目标；`遥` S2 等永续治疗技能按持续治疗处理。
- 高台输出对所有已规划阻挡点的覆盖是强排序项，不是协议硬约束；地图无可行点时保留合法候选。

### 撤退和救场

- 部署位满且后备主力可部署时，优先撤退非目标前格的先锋；其次周转非前线、非持续治疗者。目标前线不会为了普通轮换主动撤退。
- 快速复活按实际技能持续时间撤退，且只在模型提供真实再部署时间时安排再次部署；未知时间不猜测。
- 计划撤退和再次部署按真实再部署时间安排；生成器不追加仅凭 `cooling: 1` 触发的未知时刻救场动作。覆盖评分只计算干员实际在场的时段。
- 动作末尾使用 `SkillDaemon` 接管自动技能。传统模式不输出 `Wait` 或 `SkillUse`。

## 验收边界

生成后先执行内部结构和 MAA 协议验证，再进入演习。只有真实三星结果能证明该候选在当前账号、练度和客户端环境下通过；静态 `100/100`、MAA 任务正常结束或观察器启动成功都不能替代演习结算。
