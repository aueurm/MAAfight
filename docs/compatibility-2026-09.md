## 必须修正的问题

| 问题 | 影响与处理 |
| --- | --- |
| `time_elapsed` 不受 MAA 读取 | 统一为 `elapsed_time`，单位为真实毫秒；旧字段明确拒绝，旧失败记录仅保留原 hash |
| 手动技能使用 `skill_usage: 2` | 该值表示自动使用指定次数，可能提前开技；显式技能改为 `0` |
| 游戏秒与 MAA 真实时间混用 | Timeline 跟踪倍速与秒表；全部条件满足后才开始 `pre_delay`，避免重复等待费用 |
| 敌人移动倍率漏读 | 保留 `options.moveMultiplier`，按基础移速 × 关卡倍率计算游戏秒位移；本次 3884 份地图均为 `0.5`，不能把 MAA 倍速再混入基础移速 |
| 地图矩阵与路线纵坐标原点相反 | 路线起终点、checkpoint 与 rune 转为内部顶部原点；导出仍从 `[row, col]` 转为 `[x, y]` |
| 数字 checkpoint 枚举错误 | 按同快照原关与复刻关的等价路线核实等待、消失、出现语义；未知类型明确报错 |
| 直线路径被过滤 | 保留有效起终点但无 checkpoint 的路线 |
| 敌人变体、格型漏读 | 按 `enemyDbRefs.level` 合并基础属性；支持 `buildableType: 3` |
| 长回费周期被改为每秒回费 | 保留官方长周期，不假造自然回费；撤退后不再持续计入覆盖 |
| 出怪动作延迟与 fragment 调度长度丢失 | 按同一游戏秒时间线保留 `SPAWN.preDelay`、兄弟动作并行和下一 fragment 起点；详见[出怪时基核验](prts-spawn-timing.md) |
| 隐藏出怪分组合并 | 按原始关卡默认配置解析 `hiddenGroup`，crisis 默认计数由错误的 46 改为 30；未知规则明确拒绝 |
| 空间可覆盖被当作始终可覆盖 | 候选评分使用实际在场时段；通往蓝门的实际出怪路线须存在可交战区间 |
| 失败画面识别回归 | 使用失败标题局部特征，恢复明亮地图上的失败识别，并防止登录、编队页误判 |
| MAA 6 配置迁移 | 支持 `gui.new.json` 当前 profile、编队栏位与 UTF-8 BOM，同时保留旧配置读取 |
| MuMu 启动请求被当成启动成功 | 从现有 Explorer 桌面启动，连接配置中的 ADB 端点并等待 `sys.boot_completed=1`；失败或超时显示原因 |
| GUI 等待模拟器启动 | GUI 监听后异步启动 MuMu，界面打开和生成操作独立；只在启动失败时显示告警 |
| `Fight times=0` 不再导航 | v6.17.5 跳过整个 Fight；改用经过任务图检查的 `Custom` 导航，确认目标详情与演习编队后执行 |
| 从结算页再次点击演习报错且乱码 | 补齐返回主页、主题终端与目标关卡导航；异常用 UTF-8 JSON 回传，不展示 PowerShell 本地化堆栈 |
| 大干员库选人用尽预算 | 减少重复计算，先完成小 beam 候选再扩大搜索；目标预算 1200 ms，只返回合法且已评分的候选 |

提高硬约束后暴露出的真实关卡失败，修在坐标与时间根因上；没有通过降低硬约束或引入旧版生成器消除失败。

移动公式另核对 [PRTS《游戏数据基础》固定版本 424874](https://prts.wiki/index.php?title=%E6%B8%B8%E6%88%8F%E6%95%B0%E6%8D%AE%E5%9F%BA%E7%A1%80&oldid=424874)。游戏机制公式与用于排序、筛选候选的伤害启发式分别记录，不能互相冒充。

## 对先前修改的判断

原工作区中，时间线覆盖、蓝门前线、对空与反隐、开局部署优先级、新 MAA 配置读取、ADB 观察重试等方向都有必要保留；它们针对的是会导致部署失效或观测失败的实际问题。

部分原实现需要纠正后才能合入：手动技能被标为自动释放一次，使用了 MAA 不读取的计时字段；失败标题新增的全屏暗色限制会漏掉明亮地图的失败；数据表、地图与敌人模型也未固定为同一快照。不能把“修改方向合理”当成“现有实现已正确”。

多样性分数、压力窗口伤害阈值和静态评分只能帮助选择候选。扩大这些指标的权重不是兼容性修复，也没有实战证据支持把它们解释为通关率。

## 支持范围

最终全量 level 解析审计中，3544 份可解析，340 份明确拒绝。按每份文件的首个拒绝原因计：未支持 checkpoint 312 份、分组关闭规则 17 份、未知难度位 10 份、sandbox 空结构 1 份。可解析不等于可生成，更不等于通关。

未支持的路径包括 `WAIT_CURRENT_WAVE_TIME`、`PATROL_MOVE`、`MAP_OFFSET_MOVE`、`WAIT_BOSSRUSH_WAVE` 及相应未知数字枚举。已有模型仍以离散移动、局部交战近似处理敌人；碎片等待、可见性、复杂地形、召唤物、特殊机制等须查看 `coverageGaps`。

上述拒绝文件中，99 个不同 level 对应当前正式索引的 140 条 stage 记录、91 个去重可见编号。其余主要为特殊模式或无正式索引的内容。新增可解析的 7 份 sandbox 只修正了禁用路线的过滤，未验证其战斗机制。

旧索引减少的 1269 条中，1147 条已不在当前 `stage_table`，122 条仍有元数据但本次上游未提供 level 文件。`SW-EV-1` 属于后者：明确提示本快照缺少关卡文件，不能借用其他关卡冒充。

固定 96 人库的十关 benchmark 为 **33/36 通过、3 项失败、0 跳过**。8 关生成并通过协议校验；H5-1 分析输出约 2.21 MB，原测试工具默认缓冲区触发 `ENOBUFS`，将上限明确为 16 MB 后分析通过。报告保留子进程错误和性能明细，不降低任何评分或多样性阈值。热运行引擎 P95 为 990.67 ms（20 次），GUI pipeline P95 为 891.77 ms（10 次），均通过原阈值。

剩余失败是 `camp_01`、`act42side_10` 生成，以及连带的十关多样性检查（32 名干员、8 套队伍，要求至少 38 名 / 8 套且十关均生成）。两关另用 5000 ms 诊断预算检查：

- `camp_01` 穷尽 36 个候选仍无可行解，全部包含 `cost_recovery_not_modeled`。关卡初始费用 50、自然回费周期 999999；当前不建模先锋技能、击杀或撤退回费。
- MT-10 完成 6 个候选，全部缺少有效对空覆盖，搜索尚未穷尽。路线中真实的 9999 秒等待展开约 10090 个时间桶；此外有 38 个睡眠格、7 个预置物与动态地图控制器，现有模型无法解释这些事件。

这些结果说明当前生成器没有找到可信候选，不证明关卡不可解。该兼容性检查不满足“十关 benchmark 全部通过”的发布条件；不能据此宣称全关卡兼容。
