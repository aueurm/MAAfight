# v2 算法边界

## 可以做什么

- 从真实关卡数据逐秒展开敌人出生、路线移动和明确等待，得到 cell × time 压力与 15 秒关键窗口。
- 使用锁定 GameData 构建的数值模型估算常态 / 爆发 / 周期 DPS、EHP、治疗、控制和范围交集。
- 使用 200 份作业编译的聚合先验评价动作形态，不检索或复制原作业。
- 用确定性 squad / joint Beam Search 比较 `(operator, skill, cell, direction)` 候选，并以费用、位置、对空、阻挡和生存作硬门槛。
- 使用真实 `killed / total` 及可选漏怪、死亡和部署失败反馈排除失败 hash、复用成功脚本或调整同 revision 的搜索排序。
- 规划中的 MAA 执行评估层可以调用外部 MAA 执行脚本，并用回调或截图观察记录真实运行结果。

## 不能证明什么

- `candidateScore` 不是通关率或预计歼灭率。
- 协议验证 `100/100` 只表示结构合法。
- MAA 任务结束不等于通关；只有回调星级、截图观察或人工记录能作为真实结果。
- 复杂技能、召唤物、特殊索敌和条件机制只记录覆盖缺口，不伪造精确结果；未知 SP 或无可验证目标窗口时不输出手动 `Skill`。
- 生成结果不是 MAA 实际执行结果。
- MAA 日常 `Fight` 导航默认是理智作战入口，不得当作默认演习评测。

## 失败策略

v2 没有旧生成器或职业基线 fallback。模型缺失、schema 不兼容、候选搜索为空、费用/覆盖硬约束不满足或协议验证失败时直接返回错误。达到 1200 ms deadline 且已有合法候选时返回 best-so-far；没有合法候选仍报错。

执行评估层默认失败策略是中止而不是冒险开打。未确认目标关卡、未确认演习入口、检测到理智药或普通作战确认时，都不得继续执行。

## 数据覆盖

`combatCoverage` 表示已部署干员具备基础数值模型；`skillCoverage` 表示技能结构化覆盖程度，无法确认的机制写入 `coverageGaps`。默认 E2 满级、技能 10、潜能 1、无模组、满信赖只用于排序，不写入 MAA `requirements`。
