# 从关卡理解到 MAA 脚本：难关演习实验

本次用真实演习检验“机制事实 → 战术约束 → MAA 动作 → 观察与修订”，再把发现转成通用生成规则。手工候选用于定位缺口；新生成器的效果单独验证。所有实测均为普通环境；不外推到磨难或其他练度。

文中部署坐标采用 MAA `[x,y]`；源码和 `metadata.defensePlan` 保留内部 `[row,col]`，由 exporter 统一转换。

## 已落实到生成器的策略

`DefensePlanner` 按真实 WALK 路径提取末端拦截格，并按实际路径覆盖集合消除冗余点。同一蓝门可以保留多个入口。11-11 自动得到三个入口 `[8,3]`、`[9,3]`、`[8,5]`，对应首次到达估计为 18.25、42.25、86.25 游戏秒；实现中没有关卡名或干员名特判。根据费用余额和后续防线的预算前瞻，必要时把紧急阻挡部署提前；空中路线、无法到位或缺少阻挡者分别保留缺口。

`SkillWindow` 把干员强度落到有限时间窗口：只计算部署后、撤退前能够产生的伤害。自然回 SP 技能的首次就绪为 `部署时刻 + (SP 消耗 - 初始 SP) / 回复速率`，后续回转使用完整 SP 消耗，并计入技能持续时间。技能范围只在有效技能时段使用，其他时间使用基础范围；手动开技采用脚本中的计划时刻。

选人使用关键窗口的平均 DPS、总伤和有效范围；技能规划比较窗口增量伤害；最终可行性和评分使用实际候选的部署时间重新计算。原有物防 / 法抗近似仍在，因此这些数字是模型估计，不能称为账号实测 DPS。未知专精、信赖、模组及复杂伤害机制继续显式披露。

第一轮新生成器实测后继续修正了供给模型与部署依赖：

- 瞬发治疗单列 `healPerTrigger` 和由 SP 限制的条件治疗上界，不能按普攻间隔换成持续 HPS。常态与技能期间治疗分别计算；条件上界仅作为支援能力，不当作保证续航。
- 描述明确的技能结束伤害从持续攻击倍率中剥离，保留无条件攻速等收益，事件伤害暂记未知；明确持续自损的技能不能作为未经续航验证的唯一常驻防线。
- 描述明确的技能外禁普攻按可追溯字段计算，保留面板攻击基准用于减防换算，但不计入实际常态伤害；明确技能结束后被击倒或自动撤退的技能不承担唯一常驻防线。
- 编队 12 人包含后备，不为遍历全部编队而依次撤退输出核心。仍允许有明确用途的非前线先锋替换与快活再部署。
- 真实防线需要续航时，医疗规划不再依赖“开局费用压力超过 0.5”这个无关阈值。手动支援技能的等待不能排在尚未部署的入口防线之前。
- 先锋、阻挡、反隐与医疗分别保留职责槽，避免反隐占用唯一医疗槽。稳定治疗覆盖按基础范围判断，不能依赖技能扩圈填补整个回转空窗。
- 支援部署必须为尚未建立的防线预留场上名额；满足费用和到位时间，仍不代表有足够部署位。
- 无 `SkillDaemon` 时，MANUAL 自动策略只计算脚本存活期间的新开技，已开启技能的余段、普通攻击、游戏 AUTO / PASSIVE 不截断。生成器可用末尾 `Output` 等待至建模路线终点；阻挡导致的额外战斗时间仍不确定。

审查中发现，技能时长的正负号不能单独决定语义：灰烬 S3、夕 S1 等负时长技能并非永续；温蒂 S2 的原始时长为 0，却有明确无限持续描述。只有可追溯的时长语义才能获得持续伤害信用。弹药、瞬发、攻击或受击回 SP 等未可靠建模的情况保留未知，不能靠假定永续抬高评分。

防线规划的单次部署余量由第一轮的 0.75 真实秒改为 1.5 秒：该轮 MAA `deploy_oper` helper 记录约为 1.2–1.3 秒。这仍是调度假设，不是精确游戏推进时间。最终动作组装后再核对预计到位时间，并写入 `metadata.defensePlan`。

适用范围明确且无冲突的 `cbuff_max_cost` rune 转成 `options.initialCostCap`，只用于开局防线：在全部入口建立前，不插入超过初始上限的高费部署。最终 `maxCost` 保持原义，动态解锁时点未建模，不把所有高费干员永久禁用。回费技能、实际 UI 抖动和解锁条件仍是边界。

12-7 基线部署了全部 8 人，没有证据说明存在费用死锁。离线 HUD OCR 并经小裁剪核对：19:43:52.847 为 `15/41、HP 3`，19:44:05.369 为 `22/41、HP 2`；helper 19:44:31.258 才结束。首次掉血早于自动策略结束，所以暂不测试“仅延长尾段等待”，它不能挽回这次早期漏怪。

## 样本和证据

固定选择用户提出的 11-11，再从本地可解析、MAA 有导航资源、第 8 章起的正常主线中抽两关。候选还须满足现有 StageFacts 的 hard/extreme 压力标签或包含 Boss；这些标签不是官方游戏难度。排除 11-11 后共 121 关。

种子为 `20260914`，按 UTF-8 的 `seed + "\n" + code + "\n" + stageId` 计算 SHA-256，升序取前两项：**12-7、12-12**。没有按演习结果重抽。随机样本集中在第 12 章，因此不能代表所有难关机制。

运行环境：MAA v6.17.5，游戏 2.7.71，Official 客户端。关卡缓存来自 `Kengxxiao/ArknightsGameData@0ef7f952dfd018392200157a5c79a6511ba69122`。用户玩家库提供拥有状态、精英阶段、等级与潜能，技能等级、专精、信赖和模组仍未知。

每次执行固定候选副本，记录文件 SHA-256、Normal 导航、目标关卡 OCR、PLAN 演习确认、动作处理日志和独立结算观察。仅在本轮首个 CopilotAction 后启动观察器，每 12 秒保存一张本地帧；不会把这些帧逐张发送到对话。

不能混同的证据：

- 静态校验通过：结构、部分地图和协议约束通过，不代表会赢。
- CopilotAction：MAA 开始处理一条动作，可能还在等费用或时间。
- deploy/skill helper 返回：执行函数返回，不是独立的画面成功确认。
- TaskChainCompleted：任务结束，不是战斗胜利。
- `Kills: k/n`：当时的 OCR 样本，末次样本未必接近结算。
- 结算三星：本次关卡、难度、候选与账号条件下完成；不是通关率估计。

本轮不从二星推算 `总敌数 - 3`，也不把失败写成实测击杀 0。

## 已验证的战术结构

### 11-11：先覆盖真实入口，再安排常驻支援

两个蓝门有三条接近走廊。普通环境全部 13 条有效地面路线分别经过 `[8,3]`、`[9,3]`、`[8,5]` 中至少一点。按蓝门数量只放两处阻挡，会漏掉实际路线。初稿下路 `[9,5]` 还漏掉一辆自行炮的转弯路线，实测前改为 `[8,5]`。

规则基线首手在上路部署涤火杰西卡，随后灵知，第三手才试图部署中央黍。演习开局约 20 秒结束；中间帧实际可见 `2/54`、生命 2 和空着的中央入口。日志显示只进入了前两名干员的部署 helper，黍仅有动作通知。

手工 v1b 改为伊内丝 `[8,3]` 先守中路，逻各斯 `[6,4]` 常驻；风笛 `[9,3]` 接上路，塞雷娅 `[8,5]` 接下路，夜莺 `[7,4]` 的基础治疗范围覆盖三处阻挡。攒到替换费用才撤伊内丝、原位补黍，最后补白面鸮和维什戴尔。实际得到三星。

整合后的生成器没有复制这份编队。实际三星稿选择佩佩 `[8,3]`、赤刃明霄陈 `[9,3]`、涤火杰西卡 `[8,5]` 守三入口，配合黑、凯尔希、赫默、Mon3tr 与乌尔比安，末尾使用 `SkillDaemon`。它验证了入口调度、供给与保留常驻核心能通过另一套阵容落地；不能把这套阵容称为最优，也不能由一场演习确定每一处规则的独立收益。

这是一整套战术替换，不能把改善全部归因于“换第一手”。终点覆盖还需满足到位时限、阻挡数、生存、伤害与治疗。低费开场也不天然正确：需要把每条路线的首次威胁时间与部署预算、MAA 操作耗时一起检查。

### 第 12 章：费用上限与中立单位改变部署依赖

12-7、12-12 的 `options.maxCost=99` 不能代表开局上限；关卡 rune 把初始上限设为 20。诺伯特平民的机制字段每人增加 2 点上限。12-7 有 11 名平民，12-12 有 9 名；这些友好实体也出现在当前解析的 SPAWN 总数中，不能一律当作待击杀敌人。

因此，“等高费主力 → 再部署负责确认、救援的低费单位”可能形成依赖环。更稳的首个实验是用 20 费以内的干员先搭建防线。没有填写 `costs` 不等于忽略费用：MAA 的 Deploy 本身仍等待真实部署卡可用；这能避免参考费用偏差造成额外等待，但不能解除真实费用上限。

12-7 另有要求至少 3 阻挡的暴虐兵，单看 MELEE 职业不能保证能拦住。12-12 的灰礼帽有 1.5 格位移，前后阻挡相隔两格值得验证；它还先纵向绕行，不能只用最后横向回门段推断所有位移。

## 可复用的转换方法

1. **保存事实及来源。** 地图、实际路线、友敌身份、rune、敌人能力、可用干员分别记录。未知专精或机制不填成默认事实。
2. **把胜利条件改写成局部约束。** 哪条路线何时必须有人阻挡，谁能承伤，哪些单位必须在同一治疗范围内，哪个低费动作是解锁后续费用的前提。
3. **先排依赖，再排动作。** 检查首次到位时限、费用余额与上限、同时部署人数、技能启动时间、换人空窗；最后才比较输出强弱。
4. **编译为 MAA 能观察的条件。** Deploy、Retreat、Skill 与官方条件字段组合；不能凭空输出“敌方半血”“污染结束”等 MAA 没有的条件。
5. **定义反证，再进演习。** 预先写清哪一帧或哪类日志会否定假设，保留失败版本。观察不到的原因维持未知。
6. **小范围修订与消融。** 首轮可探索整套策略；得到可用方案后，再尽量只改一个战术因素，检查其必要性与代价。

| 游戏判断 | 可用的 MAA 表达 | 仍需核实的边界 |
|---|---|---|
| 首波必须先守某个汇流口 | 靠前的 Deploy、合法位置与朝向 | 动作通知不代表到位；需留 UI 操作余量 |
| 换人前先准备替换预算 | Retreat 带 `costs`，紧跟 Deploy | 两次操作不是原子替换，中间仍有空窗 |
| 核心技能需要暖机并长期输出 | 较早部署、取消无收益撤退 | 技能等级未知时用范围而非精确开启秒数 |
| 技能就绪即用足够可靠 | `skill_usage: 1`，末尾 SkillDaemon | 不能保证避开波次空窗或识别特殊机制 |
| 爆发必须等已校准的窗口 | `skill_usage: 0`，显式 Skill 配条件 | 多条件为 AND；不能同时让 MAA 提前自动开技 |
| 以时间控制动作 | ResetStopwatch、`elapsed_time` | 单位为真实毫秒，二倍速不能直接照搬游戏秒 |
| 以战况进度控制动作 | `kills` | 同一数值不能识别特定敌人、残留污染或平民状态 |
| 先确认平民再用高费卡 | 低费防线在前，高费 Deploy 在后 | 当前原生条件没有直接的“已救人数/当前费用上限” |
| 减少不必要的费用阈值误差 | 普通 Deploy 依赖真实 available | 仍可能等待真实不可能达到的费用，需静态排除依赖环 |

本轮修复了 DeepSeek 最终 Prompt 中的一个直接冲突：显式 Skill 曾被要求搭配 `skillUsage=2`，与基础 Prompt、编译器要求的 0 相反。现在统一为 0。该修复有请求内容回归检查；本轮未调用 DeepSeek API，因此不声称验证了模型生成质量。

## 保留的探索方向

| 方向 | 最小可验证办法 | 限制或当前不采用的原因 |
|---|---|---|
| 入口时限与费用账本 | 检查每条路线第一名威胁到位前是否能完成防线 | 最有直接证据；仍需容纳回费技能和 UI 延迟 |
| 机制标签进入规划 | 先覆盖费用上限、友好平民、最低阻挡数 | 标签要有原始字段依据，不等于完整模拟 |
| 常驻核心与撤退收益 | 比较保留核心和轮换版本的实际末波表现 | 永续技能可能在原候选撤退前还未暖机 |
| 低费稳态与昂贵爆发 | 在同关比较两类完整方案 | 强力干员能绕过部分机制，不能证明模型理解了机制 |
| 维什戴尔等重火力的必要性 | 固定已成功方案，删去一个部署做消融 | 少一次部署也改变费用和交互时序，需保留差异说明 |
| 更前置的击杀线 | 只移动一组前线，观察污染是否远离核心 | 会更早接敌，也可能超出治疗范围 |
| 自爆诱导 / 高生命炮击诱饵 | 分别验证一次诱爆和实际炮击目标 | 不能套用“最后部署者吸火力”；需当前目标规则证据 |
| 阿勒黛的卫护等关卡道具 | 单独确认选卡、目标与护盾效果后再混入战斗 | 不是普通干员，当前实体与坐标语义未验证 |
| 沉默处理机制 | 先核敌人免疫与可沉默技能，再对照一轮 | 不能因为技能写着沉默就假设能消除自爆、污染或隐匿 |
| 元素医疗处理污染 | 先确认伤害是否为元素损伤 | 11-11 资料只证明持续损失生命，不能直接推出元素奶有效 |
| 事件驱动的手动爆发 | 稀疏观察定位可靠窗口，再编译条件 | 击杀数不等于 Boss 身份或 HP，时钟也会受暂停影响 |
| 低截图的本地 HUD OCR | 对已有帧离线读击杀、生命、费用 | OCR 错误和短暂事件会漏检，未知值不补猜 |
| 学习候选排序 | 先积累同关可归属的成对实测 | 当前样本少，不能拟合或宣传通关概率 |
| 单次伤害与攻击频率分别计算 | 固定敌人物防，比较高倍率重击和多段低伤 | 当前用普通攻击减伤比例缩放技能 DPS，会忽略破甲阈值；需可靠的逐击数据 |
| 弹药与蓄力总伤预算 | 用弹药数、每击倍率、目标数和实际攻击间隔做守恒检查 | 弹药持续时间依赖索敌，不能直接套固定秒数 |
| AoE、弹射与重叠命中 | 按窗口同时在范围内的敌人数估计上下界 | 最大目标数不等于每次都打满，爆炸重叠也不能随意相乘 |
| 生存与治疗回转联合规划 | 检查每条前线受击峰值与可覆盖的治疗窗口 | 平均 HPS 难以表达一击致死、治疗锁定和不可被治疗职业 |
| 低练度敏感性分析 | 固定同一战术，降低等级 / 技能等级后比较可行窗口 | 玩家技能资料不全时应给区间，不能默认专三等于真实练度 |
| 故意漏怪后补救 | 在非三星目标下记录生命预算与可接受漏怪 | 当前目标为三星演习，不能把可存活路线当成功稿发布 |
| 借助好友助战 | 把缺失核心作为明确的外部编队条件再实验 | 当前 fixed 12 人默认来自玩家库，助战选择与可用性未接入 |
| 暂停 / 子弹时间降低操作误差 | 测量部署交互占用的真实时间与费用漂移 | 会改变秒表与操作顺序，不能仅改估计值就宣称更稳定 |
| 视觉识别 Boss 状态后开技 | 先离线标注可靠状态，再用少量帧验证 | 当前静态 MAA 脚本没有通用敌方血量条件，需执行层扩展 |
| 强化学习 / 全局黑盒搜索 | 先在单路线微型环境验证 | 真实演习慢，且没有可信完整模拟器；暂不开展大规模试错 |

不应先扩大 beam 或提高候选评分来掩盖这些缺口。更有依据的方向是：先让入口、费用和实体身份成为可检查约束，再让语言模型提出战术假设，由确定性代码验证和编译，最后以真实演习反证。

## 工程验证与未解决边界

最终检查的机器可读记录见 [validation.json](experiments/hard-stages-20260914/validation.json)。Jest 与构建验证的是实现约束；benchmark 的生成失败仍保留，不能与三星演习合并成一个通过率。

最终完整构建、44 套测试的 474 项断言以及 200 份语料审计通过。十关 benchmark 为 **27/32**，历史为 **33/36**：保留 camp_01、MT-10 与多样性失败，另有 GT-EX-1 和 3-8 生成失败；后两关未生成脚本，连带不再执行其 validate / analyze，所以分母减少 4。当前 32 名不同干员、6 套不同编队低于门槛。热 P95 为 engine 902.03 ms、GUI pipeline 1016.03 ms，仍通过各自的 1200 / 2000 ms 门槛。

GT-EX-1 新暴露的生成失败有两层原因。原始路线含 `WAIT_CURRENT_FRAGMENT_TIME.time=140`，但 adapter 没有保留该时间，RouteTimeline 只记录 gap 并跳过等待，导致两只预置敌人被估成很早进蓝门。旧 Feasibility 又把首手重岳尚未启动的 S3 范围算在开局，虚构了对这两路的伤害；修正基础与技能范围后，这个假阳性消失。

仅在内存假设“等到 t=140”，相同候选能通过当前 Feasibility，但这不是时钟语义已确认的证据。[上游 issue #63](https://github.com/Houdou/prts-map/issues/63) 也未明确 fragment 时钟原点。因此本轮保留该关生成失败，既不回退范围修正，也不硬编码等待时间。后续需要确认 fragment 的归属，并验证延迟出生、跨 fragment 与超过目标时刻等情况。

3-8 的问题不同：最终 benchmark 拒绝 18 个候选，唯一一次定向重试拒绝 20 个候选后同样超时。上一版的脚本 `899231f4…933d4` 在当前模型和正确禁普攻语义下仍通过 Feasibility，说明有限搜索遗漏了已有可行方案；不能把失败说成关卡无解。当前缺伤集中在 routes 4 / 9 / 10，具体由哪项改动改变搜索结果尚未证实，作为搜索覆盖退化保留。

固定候选与当前候选的数值对照见 [3-8 诊断](experiments/hard-stages-20260914/main-03-08-diagnostic.md)。后续优先补入最低阻挡与阻挡后交战约束，并恢复有限搜索对已知可行方案的覆盖，再扩大关卡样本。

第 12 章的最低阻挡数、友好单位状态、费用动态解锁和位移仍未完整进入硬约束。camp_01、MT-10 的生成失败和多样性检查也尚未解决；PR 保持 draft。

## 本地复现

完整实验工作区位于 `.maafight/experiments/hard-stages-20260914/`，实际运行记录位于 `.maafight/experiments/root/hard-20260914/`。安装目录 `D:\app\MAA` 始终只读，覆盖、日志、候选和观察帧写项目工作区。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/enter-practice.ps1 `
  -MaaDir D:\app\MAA -Stage 11-11 -Difficulty Normal -ScriptPath <候选绝对路径>
```

运行前确保无其他任务控制游戏。若停在上轮结算页，先确认结算再点击继续；本轮曾遇到从失败结算页执行 StartUp 失败，未进入战斗，单独记作操作准备失败。手动技能脚本可能在战斗结束前完成任务，应另行有界等待真实结算。
