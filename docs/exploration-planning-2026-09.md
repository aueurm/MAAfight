# 规划、战斗模型与搜索方向探索

日期：2026-09-13。兼容修复基线：`ceb8da1c3842b3e1f35fda6a4c68bb6144ecdbe7`。

本次最明确的新证据是：**MT-10 现有逐秒压力可以压缩为少量区间，并完整还原；这能减少重复查询，但尚不能解决关卡机制缺失或证明可通关。**

建议优先研究费用来源、无收益撤退和长等待表示，再决定扩大搜索还是补战斗模型。下文保留了成本很高、当前条件不具备的方向，并分别说明原因。所有尚未实施的收益都属于假设，成本是相对工程量，不是排期承诺。

本轮只新增独立离线实验和本文档，没有修改生产代码、候选或硬约束，没有调用收费 API、联网或操作游戏。本轮没有新增实战结论；实际演习由主任务统一执行、记录，不能用本文实验代替。

## 已有证据和边界

| 编号 | 已观察事实 | 能支持什么 | 不能支持什么 |
|---|---|---|---|
| E1 | 当前 MT-10 压力为 10090 个桶，末时刻 10089；路线 23、24 保留 `WAIT_FOR_SECONDS=9999`，仍有 `route_timeline_limit` | 长等待引入大量重复数据，且截断边界尚存 | 不能把等待直接缩短，也不能认为真实战斗持续 10089 秒 |
| E2 | 既有固定 96 人库实验中，camp_01 在 1200 / 5000 ms 目标预算分别构造 5 / 36 个候选，全部存在 `cost_recovery_not_modeled` | 当前费用模型无法解释这些候选 | 不能证明关卡不可解，也不能认为增加预算必然有用 |
| E3 | 同一实验中，MT-10 分别构造 1 / 6 个候选，均存在 `critical_window_missing_anti_air`；5000 ms 档 JointPlanner 占记录耗时约 78% | 构造开销高，同时存在覆盖失败 | 不能把全部失败归因于速度；更快也可能只是更快得到失败候选 |
| E4 | 1-7 的 340 人库候选部署上限为 8；模型预计逻各斯在 142–158 游戏秒、酒神在 158–174 游戏秒驻场，另有 2 人未部署 | 队伍有剩余部署价值与轮换顺序问题可研究 | 不能把这些预测时间当实测，不能从静态合法推断三星 |
| E5 | 1-7 的 `timing=0` 来自 `clamp(100 - lastDeployment * 2.5)`；候选含技能、召唤物、满信赖和技能 10 级假设缺口 | 单个分项可能失去区分度，需要核对评分与用户目标是否一致 | 不能将分数解释为成功概率 |
| E6 | 当前模型已有原生动作导出、费用时间线、范围覆盖、反馈和有限技能规划，但未完整模拟击杀、阻挡、索敌和阶段切换 | 可以增量补足有实测价值的机制 | 不宜承诺短期实现完整游戏模拟器 |

E2 / E3 来源于本机 `.maafight/integration-20260913-camp-mt-boundaries.json`，不是本轮重新跑出的搜索结果。E4 / E5 来源于本机 `output/.candidates/compat-1-7-20260913.json` 和 `.maafight/integration-20260913-gui-generate.json` 的只读复核。

一个费用缺口的具体例子：camp_01 已保存的首个样本累计部署费用为 210，初始费用为 50，自然回费周期为 999999 秒。在**不计返费和其他收入**的样本账本中，需另外解释 160 点费用来源。这个数字只描述该样本，不是关卡最低费用，也不证明必须使用特定先锋。

## 离线实验：MT-10 的连续相同压力区间

实验使用当前源码内存转译和本机已锁定的关卡缓存。加载器遇到 cache miss 直接报错，禁止网络；没有运行候选搜索。

将相邻且 `cells` 的每个字段完全相同的桶合为 `{start, count, cells}`。不同的路线、敌人、机制、覆盖缺口会阻止合并。缺失的时间桶仍保持缺失，不跨空洞合并。15 秒关键窗口从区间重新计算。

| 项目 | 逐秒表示 | 区间表示 | 观测说明 |
|---|---:|---:|---|
| 时间桶 / 区间数 | 10090 | 163 | 记录数减少 98.38% |
| cell 记录数 | 21257 | 1292 | cell 的各字段未删减 |
| 紧凑 JSON 字节数 | 6301303 | 479300 | 减少 92.39%，是序列化体积，不是堆内存测量 |
| gzip 字节数 | 60515 | 10356 | 原始 JSON 本身也能被通用压缩显著压缩 |
| 144 个查询的一批中位耗时 | 32.934 ms | 2.203 ms | 一次预热后，5 次交替顺序测量；仅此查询原型约 14.95 倍 |

最长相同状态覆盖第 199–10088 秒，共 9890 个桶。原始压力构建耗时 36.260 ms，另行编码 21.588 ms，解码 2.842 ms；这些单次时间不是稳定性能承诺。

验证结果：

- 解码对象与原始对象深比较完全相同，JSON SHA-256 均为 `ac0d84441c34d6144bd8de481724e682bbe04225ede17be6d9b40b070f1b2cfc`。
- 673 个 15 秒关键窗口从区间重新计算后完全相同；`route_timeline_limit` 原样保留。
- 额外空洞样例通过，证明相同状态之间的缺失时间不会被补入。
- 144 个查询覆盖 3 个参考干员、合法部署格、4 个方向、完整与局部时段，包括半秒边界；其中 85 个查询非零。
- 区间加权查询与逐秒基准的最大绝对差为 `9.19e-8`，最大相对差为 `1.80e-13`，低于预设 `1e-9` 相对容差。

这里的“无损”严格指**现有压力对象的可逆表示**。查询将重复加法改为乘法，浮点累加顺序发生变化，因此查询分数采用容差验证，没有宣称 bit-exact 相等。若未来用于确定性排序，需另查临界并列和 tie-break 是否变化。

本原型先构建逐秒数据再压缩，所以没有省掉路线展开成本。真正接入 JointPlanner 还需要区间交集、部署／撤退边界切分和覆盖重叠计数；当前实现仍按 `time:cell` 键保存覆盖。不能把约 15 倍查询提速直接套到搜索端到端耗时。

压缩也没有解释圣徒像、睡眠格、预置物或关卡控制器的真实行为。`9999` 秒等待和 `route_timeline_limit` 均保留，更没有放宽对空门槛。

实验文件按要求保留在本机被 Git 忽略的 `.maafight/experiments/engine/`：

- `sparse-pressure.cjs`：可审查的独立实验脚本。
- `mt-10.report.json`：源码 revision、文件 hash、地图 hash、完整测量与限制。
- `mt-10.dense-pressure.json`：原始逐秒压力。
- `mt-10.sparse-pressure.json`：压缩后的压力。
- `mt-10.queries.json`：逐项查询结果和数值误差。

复现命令：`node .maafight/experiments/engine/sparse-pressure.cjs MT-10 5`。需已有本机依赖与锁定缓存；该目录未自动加入 GitHub，因此公开文档中的测量应结合本机原始数据审查。

## 方向一：补足会影响计划有效性的事实

以下方向均未接入生产。“可行”表示实现路径清楚，不表示实战收益已经验证。

| 想法与用户收益 | 证据 / 前提 | 成本或当前不可行原因 | 最小验证办法 |
|---|---|---|---|
| 1. 连续压力区间：让长等待关卡查询更快，减少重复对象 | E1、E3；本次原型已验证现有数据可逆 | 中等。要改消费方，保留缺口与边界；直接从原始事件构建比事后压缩更难 | 将同一小段 JointPlanner 覆盖计算做区间版原型，固定输入比较覆盖集合、排名、耗时；暂不改生成入口 |
| 2. 关卡阶段状态机：依据阶段事件启用敌人、地格和预置物 | MT-10 有长等待、睡眠格及控制器记录；当前静态地图不解释这些语义 | 高。需要可靠的事件语义和实战观察；仅从 `9999` 推测事件不充分 | 只选一种睡眠地格或一个阶段切换，对照资源与演习日志记录变化；不能解释的事件继续报缺口 |
| 3. 有来源的 DP 账本：让停自然回费关卡获得可信的部署时间 | E2；TimelinePlanner 主要计自然回费和部署支出 | 中高。自回 SP 的明确回费较易；击杀回费依赖战斗，返费比例与再部署也需区分 | 从一个回费技能开始，核对初始 SP、每次收益和原生开技动作，逐笔解释 camp 样本费用；收入无证据时保持拒绝 |
| 4. 按实际练度计算：避免技能等级、潜能、模组未知导致计划过于乐观 | E4 / E5；玩家记录缺少 skillLevel 时按 10 级，信赖默认满值；部署成本可由 player.cost 覆盖 | 中等，主要难点是信息缺失。不得把缺失值默认为玩家真实配置 | 固定一个候选，分别输入已知技能 7 / 10 级和真实费用；列出受影响的 SP、开技窗口和部署时间，再做一次练度已确认的演习 |
| 5. 原生动作与 SP 联合排程：在敌人关键波到来前开技，同时不阻塞后续部署 | E4；当前手动技能在早于最后部署时可能标记 ordering_unverified 并交给自动模式 | 高。MAA 动作串行，条件为 AND；攻击／受击回 SP 不能从墙钟直接推出 | 仅 2 名干员、1 个自回技能，编译为官方动作并核对回调顺序；攻击回 SP 继续保持未知，不偷偷改成按秒计 |
| 6. 召唤物与装置的独立实体：正确计算费用、占位、部署上限和收益 | E4；酒神等候选存在 summon_or_token 与技能 blackboard 缺口 | 高。召唤物不一定占部署数，地格限制、寿命和自动生成规则各异 | 只选一种无复杂条件的装置，建立实体生命周期表，在小关确认费用和部署数；不直接覆盖全部召唤职业 |
| 7. 局部阻挡与击杀过程：减少“敌人自由走过所有格子”的偏差 | E6；现有压力不因己方阻挡和敌人死亡改变 | 高，但可局部实现。阻挡数、击杀顺序和攻击间隔相互影响，完整模拟过大 | 一条路线、一个地面阻挡者、数个同类敌人，预测首次接触／死亡／漏怪区间，再与一轮演习核对 |
| 8. 索敌和伤害时序：减少同一份 DPS 被错误用于所有目标的风险 | 现有伤害主要由覆盖、平均防御和窗口聚合估计 | 高。攻击前摇、弹道、群攻目标数、闪避和特殊优先级都可能改变结果 | 单干员对两种防御敌人，验证索敌顺序与首次击杀时间；先明确误差，不据此给全关通关概率 |
| 9. Boss 分阶段计划：将无敌、转阶段、复活等视为计划边界 | E6；持续 DPS 无法解释长无敌与特殊转场 | 高，且需逐机制维护。缺少阶段信号时暂不能自动保证切换 | 先选只有一个明确转场的 Boss，记录前后可攻击状态，并生成两段独立子计划；复杂控制器仍保留缺口 |

## 方向二：让候选本身更值得执行

| 想法与用户收益 | 证据 / 前提 | 成本或当前不可行原因 | 最小验证办法 |
|---|---|---|---|
| 10. 蓝门与交汇点分工：先决定谁守哪条出口，再选技能和朝向 | E4；路线数量不等于独立防线数量，1-7 有 26 条路线但只有一个蓝门 | 中等。路线图能复用，但飞行、传送和动态地格不能统一当普通通路 | 用 1-7 与一个多蓝门关对照，检查每个出口的首个可用阻挡者和费用；不先追求总分提高 |
| 11. 撤退需要明确收益：避免刚部署的核心技能还没启动就换人 | E4；逻各斯模型驻场 16 秒，而所选 S1 初始 0 / 60 SP | 中等。比较留场与替换需考虑未来压力、返费和技能机会；不能一律禁撤退 | 固定 E4 的阵容与点位，只比较“原轮换”与“保留逻各斯”两个离线方案；静态都合法后，由主任务选一次小关演习，不改已有结果 |
| 12. 少部署、少操作的候选：固定 12 人编队中保留真实后备，避免为用满人而用人 | E4；已有 2 人未部署，另有后半段部署可能很晚 | 中低。保持 fixed 12、groups 空；减少部署不能依靠删掉必要覆盖换取低动作数 | 同一 12 人库生成 6 / 8 / 10 次部署的合法候选，比较开局成形和覆盖缺口，再用同关实测核对；动作少不是自动成功 |
| 13. 对未知参数保守的候选：练度或机制不完整时优先选敏感性更低的计划 | E5；当前存在默认技能等级、满信赖和部分技能模型 | 中高。需明确哪些参数有可信上下界；不能把所有未知设最坏后拒绝一切 | 只对已知缺失的技能等级做 7–10 级情景，统计哪些动作条件和硬约束改变；保留所有情景与未知标记 |
| 14. 多目标候选：让用户在易执行、少假设、较早成形和费用余量之间选择 | E5；单一加权分可能掩盖 timing 饱和和未知技能代价 | 中等。不能直接将不同量纲分数命名为胜率；选项太多也增加负担 | 固定 20 个合法候选，保留 3 个不被其他方案全面优于的方案，给出实际动作差异；先验证解释是否真实对应代码 |
| 15. 可解释的阶段模板：复用“开局防线 → 稳定输出 → 转场替换”这类结构 | 现有 corpus 使用聚合动作先验，不保存可执行战术结构 | 中高。模板可能过拟合旧关卡；不能把公开作业换名当通用生成 | 先人工定义一个结构模板，只约束职责顺序，让当前引擎完成选人点位；在两个地图结构相似但敌人不同的关上检验 |
| 16. 计划敏感性解释：告诉用户换一个干员或技能会影响哪段防线 | 当前候选含 playerOperatorsUsed、operatorGaps 和 coverageGaps，可作为解释入口 | 中等。敏感性要重新计算相关依赖，不能凭文本臆测因果 | 固定 1-7 候选，只替换一个干员，在相同地图 hash 下比较费用、覆盖和技能窗口，输出可核验的差异 |

## 方向三：用更少计算找到不同的合法计划

| 想法与用户收益 | 证据 / 前提 | 成本或当前不可行原因 | 最小验证办法 |
|---|---|---|---|
| 17. 跨候选复用覆盖特征：同关同技能的范围、方向和压力交集算一次 | E3；JointPlanner 对每个 pick 重建 byCell 和覆盖 Map | 中等。缓存键须含地图内容、技能范围、对空能力和 bias，且控制内存；时序变化不能误复用 | 固定 6 个候选集合，只统计重复特征数并比较只读缓存原型；核对所有覆盖键和得分，记录成本转移 |
| 18. 按行为保留搜索多样性：保留不同防线、开局和回费方案 | 现有 beam 主要按干员集合差异及评分筛选；阵容不同可能部署行为相同 | 中等。行为签名过粗会误删有用候选，过细则无效果 | 固定预算，记录候选首 3 手、蓝门分工和关键窗口覆盖签名；比较独立策略数量与通过硬约束数量，不只看分数 |
| 19. 局部修复已有候选：实测失败后只换影响失败位置的一小部分动作 | 现有反馈已有失败 hash、路线权重和排序偏置基础 | 中等。根因错归会让修复反复；必须保留整条验证链 | 用已记录的一次具体部署失败或漏怪路线，只枚举一个点位／顺序／干员变化，保存失败证据与每个变体的验证结果 |
| 20. 以工作量管理 anytime 搜索：更稳定地先给出首个合法候选再改进 | 大库兼容修复已采用渐进 beam；1200 ms 是协作式目标，E4 曾记录 1333 ms | 中等。严格墙钟上限与确定性冲突，额外进程也有开销；没有合法候选仍需失败 | 固定 96 / 340 人输入测首个合法候选时间、总时间和检查间隔最大耗时，区分构造、校验、评分；不单纯加大预算 |
| 21. 约束冲突解释：把“生成失败”缩成玩家能采取行动的少数原因 | E2 / E3 有稳定拒绝原因，但尚未给出最小冲突组合 | 中等。启发式门槛并非数学不可满足证明；不应把模型缺失说成玩家库不足 | 在一个失败候选上逐项记录覆盖、费用与能力证据，诊断“当前候选缺什么”；若做约束消融，仅用于解释，放宽后的候选不得导出 |
| 22. 小规模精确求解：对已选干员和少数格子求部署顺序或分工最优 | 选人、点位、时序组合爆炸，局部结构可以有限离散化 | 高。完整 CP-SAT / SMT 模型需要大量机制编码，整体求解可能比 beam 慢 | 固定 4 名干员、6 个格子、3 个时段，枚举或求解覆盖与费用问题，与 beam 比较漏掉的合法解；不先引入大型依赖到生产 |

| 23. 为信息量选择演习：用一轮实战区分两个明确的机制假设 | 实战次数、时间和日志处理都有限，当前有费用、开技、轮换等可检验假设 | 中等。必须预先写出观察点，不能看完结果再改解释 | 只选一个变量，例如“保留核心输出是否覆盖末波”，固定地图、玩家库和其余动作；记录 hash、观察证据和仍不能排除的解释 |
| 24. 用反馈训练候选排序：逐步学习哪些静态指标值得信任 | 现有反馈接口可提供真实结果，但当前样本规模和覆盖尚不充分 | 高。样本少、重复关卡多、玩家练度混杂容易学到偏差；不能直接训练通关概率 | 先离线统计反馈量和关卡分布，按关卡留出评估；仅预测成对候选优先级，硬约束继续由确定性代码执行 |
| 25. 强化学习 / 自博弈规划：自动发现人难想到的部署组合 | 若有高保真模拟环境和大量可重复局面，长期可能有价值 | 目前缺少可信模拟器、奖励定义和足够样本；真实游戏试错资源不足，直接启动训练不可行 | 先在人工定义的一条路线微型环境中验证学习能超过明确基线，同时报告模拟与真实差异；未跨过差异验证前不投入大规模训练 |
| 26. 直接黑盒实机优化：把演习结果当目标函数搜索动作 | 不必一次建完战斗模型，理论上能利用真实反馈 | 当前不适合全局搜索。单次演习慢，交互失败与战术失败混杂，样本代价高；截图传输还可能触发 413 | 只比较两个预先验证合法、单变量差异的候选；优先回调／日志，最多保留必要结果图，不循环全量截图 |
| 27. GPU 或多进程大搜索：加速大量候选比较 | E3 表明计算集中于 JointPlanner，但目前大量工作是 JS Map、对象和串行约束 | 高，收益未知。GPU 数据搬运、多进程初始化与重复内存可能吃掉节省；扩大并行不补机制缺失 | 先将一个只读覆盖核转为紧凑数组，测其占总耗时与批量大小；达不到足够占比时保留该想法但不实施 |
| 28. 让语言模型提出战术假设：补充确定性搜索未覆盖的方案族 | 已有 deepseek-core 和确定性编译，可承载结构化建议 | 高且需额外调用预算。自然语言推理并不等于战斗事实，模型也可能反复提出同一方案 | 先用本机已有输出离线分类，检查能否提出与 beam 不同的职责分工；任何新计划仍过同样的地图、DSL、协议与实战门槛，本轮不调用 API |

## 推荐验证顺序与停止条件

1. **先做容易区分真假的改进。** 对 E4 只研究一项撤退是否必要，对 camp 只补一个有明确来源的 DP 收入。收益观察分别是实际是否完成关键输出、费用账本是否闭合，而不是候选分数增加。
2. **将稀疏表示推进到一个消费方。** 当前可逆压缩已测；下一步仅比较同输入的覆盖查询和排名。若结果改变超过数值容差或没有端到端收益，先停在原型，不全面改架构。
3. **MT-10 先解释阶段事件，再讨论解除拒绝。** 对空失败可能来自实际选位，也可能与尚未解释的阶段对象有关，需要逐条证据。省时与补机制可以并行，不能互相替代。
4. **只有可观测的小模型稳定后，再投入更大模拟或学习。** 至少先能区分操作失败、部署失败、时序偏差和战术失败；目前没有证据支持优先做全局 RL、全关精确求解或 GPU 改写。

若最小实验没有产生可复核的差异，就记录“尚未支持”，不把方向删除，也不通过放宽硬约束制造正结果。真实三星、击杀数、漏怪和候选排序分分别记录。
