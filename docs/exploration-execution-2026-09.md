**执行与反馈应先保证“发生了什么”记录正确，再扩大自动化。** 最有依据的近期方向是保留观测来源、让结算后的再次导航成为明确流程、将人工干预绑定到实际执行记录，以及用单变量演习验证小改动。视频级因果识别、通用视觉导航和中途续跑也值得保留，但目前需要额外的状态与验证能力。

**证据与边界。**

用户从 1-7 结算页再次点击 GUI 演习，遇到要求手动进入详情页的错误。补齐经过官方资源检查的 `Custom` 导航与返回流程后，结算页到演习编队已验证；随后从游戏主页实际点击 GUI 按钮，完成 1-7 三星演习。更广的页面与关卡覆盖仍是下列方向，已实现的受限导航详见[执行层文档](maa-execution.md)。

此前候选 hash 前缀 `e9491e` 的 1-7 三星演习已有真实结算证据。**三星结果是真的，反馈中的 41 / 41 是规则换算，未通过 OCR 读取。** 这两句话可以同时成立；不能因击杀来源不准确而抹掉三星记录，也不能将三星包装成采集到了精确计数。

主 agent 的隔离实验只输入二星类别，没有提供击杀数；当前 `FeedbackStore.recordPracticeTestResult` 对总数 3、10、41、400 分别保存 killed 为 0、7、38、397，均标记 `usableForLearning=true`。完整结果见 [综合探索报告](future-directions-2026-09.md)；本机原始结果为 `.maafight/experiments/root/feedback-star-only.json`，使用合成关卡，没有写入用户正式反馈库。本文直接使用该证据，不重复进行实战或写入实验记录。

只读代码核对还发现两个需要分开设计的现状：`RunResultStore.summary` 的结果分母包含 `execution_error`；`screenObserver` 会判断结算标题和星级，但不读取战斗中的敌人数字。因此，“本次任务没有成功”“进入战斗后没有三星”和“看不到结算”不能被当作同一种失败样本。

下列方向均为建议。收益不表示已实现，最小验证也不表示已经执行。与 [数据方向](exploration-data-2026-09.md) 的通用版本身份、评估分层不同，这里重点讨论执行时序、证据形成和反馈消费。

| 6 | **记录首次可观测偏差。** 为“部署没发生、画面停滞、首次漏怪”等事件保留时刻，缩小诊断范围 | 只有最终星级难以区分选人、部署时机与执行入口问题；当前过程帧可用于离线复查 | 中成本；“首先观测到”不等于“真实第一原因”，采样间隔会漏掉短事件 | 在有清楚人工标签的短片段中检查一个事件类型，例如部署前后占位变化；报告检测延迟和未知区间 |
| 7 | **按已确认页面推进导航流程。** 支持从结算、首页、详情、编队等不同起点再次演习 | 用户的新问题发生在上一场结算页；仅支持详情页起点会导致操作闭环中断 | 中成本；返回动作可能触发不同弹窗，不能无限连点或把一个页面识别错误传递到后续启动 | 用隔离页面 / callback fixture 验证各起点的下一状态；再由 runner 检查“结算后再次运行”这条实际路径 |
| 8 | **把导航能力绑定到资源版本和目标任务图。** 按官方资源可核验的行为扩展支持，而非维护大量坐标 | 已核查 `Custom` 任务、继承、异常和返回路径，1-7 已实测；不同 MAA 版本的任务行为已变化 | 中成本；资源存在不代表所有分支安全或可用。遇到未知表达式、战斗入口或未审计分支应保持人工入口 | 从已通过的主线图和危险反例继续扩展离线审计；资源 hash 改变时重新判断，不沿用旧通过结论 |

| 11 | **记录实际执行副本与干预谱系。** 将候选、运行副本、手动删改和运行时干预关联，防止把改过的成功归给原稿 | GUI 已固定运行副本并检查 hash，这是基础；动作删改或人工开技会改变实验处理条件 | 中成本；脚本 hash 不能自动记录鼠标干预。需单独的 intervention 记录，不能声称 hash 已捕获所有行为 | 对原稿和删改稿分别生成 hash，结果只归属实际运行副本；一次人工干预将该运行标记为不能直接与未干预组等同比较 |

| 18 | **短视频级动作与因果诊断。** 未来识别敌人轨迹、干员死亡、技能和手动干预，解释失败发生过程 | 当前稀疏截图与最终星级难以提供完整时间线；现有代码没有这些识别能力 | 高成本、目前不适合直接驱动学习：遮挡、特效、帧率与游戏机制会造成歧义，精确因果也不能仅由画面保证 | 只选择数秒且事件清楚的一段脱敏片段，比较人工标签和模型事件；未达到一致性要求就停在辅助复查 |
| 19 | **通用视觉导航。** 在官方导航不覆盖的活动、主题或新 UI 中推断如何到达演习入口 | 用户需要不同页面起点；受限任务图无法覆盖所有未来 UI | 高成本且暂不宜作为默认入口：视觉误判可能进入普通作战，长链推断累积错误；本轮没有实现此能力 | 先在静态页面或模拟状态机中预测下一步，不发送点击；每一步需要可核验后置状态和停止条件，再考虑极小范围验证 |
| 20 | **断线后的受限恢复与战斗中途续跑。** 减少环境中断后的重复操作 | 运行跨 GUI、helper、MaaCore、模拟器和游戏；任何一层退出都可能丢失控制状态 | 前半部分中成本，完整中途续跑当前可能不可行：只有画面不足以重建 MAA 动作游标、秒表、费用和已触发条件，重复动作也不可回滚 | 先只恢复“读取当前页面、重建观察、展示上次已确认阶段”；无法证明动作状态一致时，不自动续发战斗动作 |
