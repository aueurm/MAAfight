# 后续方向与实验结论

日期：2026-09-13。探索开始于兼容修复提交 `ceb8da1` 和 GitHub PR #1 建立之后。本文区分当前可用能力、实验原型和尚未实施的想法；不把候选评分解释为通关概率。

建议优先做三件事：让反馈保留真实观测的含义，验证局部动作删减是否有益，把已验证的稀疏压力原型接到一个实际消费方。全关卡模拟、强化学习、GPU 大搜索等方向保留在详细报告中，但目前缺少必要的数据、环境或收益证据。

## 实战对照：删除 1-7 的后期轮换

先写明差异再执行：保留同一关卡快照、12 人编队、前 8 次部署、全部费用条件与 `SkillDaemon`，只移除“撤退逻各斯、部署酒神、撤退酒神、部署歌蕾蒂娅”四个后期动作。两份脚本都通过完整地图校验与 MAA 协议校验，同时在场不超过 8 人。原候选文件未修改。

| 版本 | 动作数 | 脚本 hash 前缀 | 入口与结果 |
| --- | ---: | --- | --- |
| 最新基线 | 14 | `e9491ea57eb3` | 从游戏主页实际点击 GUI 按钮，自动导航后完成 1-7 三星；15:21 回传结果 |
| 单次消融 | 10 | `b652edbd043d` | 从上一轮结算页通过同一 GUI 服务的 API 发起，自动导航与演习验证通过；15:26 回传三星 |

消融由 subagent 独立执行，使用固定运行副本，其 hash 与新候选精确匹配。没有为手工改写稿伪造生成记录；GUI 保留“找不到该 hash 的 generation、未写入训练材料”的警告。前后反馈库完全相同，基线反馈未被消融结果污染。

本次证据支持：这四个后期动作在这一次 1-7 演习中并非获得三星的必要条件，精简候选值得进一步研究。尚不能证明删减提高成功率、适用于其他关卡，或可以全局移除撤退逻辑。两个入口不同，也没有对照精确战斗时长，不能根据请求总耗时声称提速。

另外，当前 MAA 的 `CopilotAction` 回调发生在等待动作条件之前，只表示开始处理动作；不能把收到某条 Deploy / Retreat 通知直接当成部署或撤退成功。后续实验若要判断“某个动作真的发生且无收益”，需要底层执行结果或额外观测。

本机原始证据在 `.maafight/experiments/runner/`：`ablation-preflight.json`、`ablation-result.json`、`ablation-maa.log`。最新基线的浏览器验证记录是 `.maafight/integration-20260913-gui-navigation-click.json`。这些文件未公开，文档只保留必要的脱敏测量。

## 反馈可信度：一个应优先修正的旧假设

主 agent 在隔离目录中调用现有 `FeedbackStore.recordPracticeTestResult`，只输入“二星”或“失败”，**没有提供击杀数**。为排除玩家差异，所有记录使用合成关卡与相同虚拟干员库，候选分数固定为 70。没有写入用户的正式反馈库。

| 敌人总数 | 输入类别 | 当前保存的 killed | 当前 ratio | 可用于学习 | 单条反馈对同分项候选的加分 |
| ---: | --- | ---: | ---: | --- | ---: |
| 3 | 二星 | 0 | 0% | 是 | -6.364 |
| 10 | 二星 | 7 | 70% | 是 | 0 |
| 41 | 二星 | 38 | 92.683% | 是 | +2.062 |
| 400 | 二星 | 397 | 99.25% | 是 | +2.659 |

四种总数下，“失败”都被保存为 killed=0，并可进入学习。直接原因是现有代码将二星固定换算为 `max(0, total - 3)`，失败换算为 0。测试还固化了这个旧行为。

因此，星级不足以支持这些精确击杀数；同样的类别会因地图总数不同产生很不同的数值标签。这里没有断言实际应该击杀多少，只证明程序在没有观测时生成并消费了一个精确数字。当前 1-7 三星演习是真实结算证据，但反馈中的 41/41 仍来自规则换算，不是 OCR 读取。

建议保留离散结果 `clear / partial_clear / failed / unknown`，给观测附加来源与置信依据；只有读到实际计数时才填 killed / total。旧的推算记录应标明来源并从精确比例学习中隔离，不能删除后假装它们从未存在。三星可用于同版本成功脚本复用，但不必为此把所有结果强制转换为击杀比例。

这是待实现方向，本轮未改变反馈生产逻辑。最小验证是用两份二星记录、一个进入失败和一个有真实计数的记录，检查只有最后一类提供精确比例；再验证成功脚本复用与历史数据读取仍正常。

本机复现：`node .maafight/experiments/root/feedback-star-only.cjs`。结果写入同目录的 `feedback-star-only.json`，每次使用独立子目录；合成输入与真实演习记录完全分开。

## 选择下一步的标准

1. 优先选择一次小实验能够明确判定的假设，例如“这个撤退是否有收益”，或“压缩是否保持覆盖集合”。
2. 先把失败原因分成输入缺失、模型缺口、搜索不足、交互失败和实战失败，避免通过增大搜索预算解决错误的问题。
3. 每次实战固定地图 / 版本 / 玩家库 / 脚本 hash，仅改变一个因素；单次三星只证明该次运行，不能估计稳定通关率。
4. 给高成本方向保留入口和停止条件。完整模拟或 RL 若不能先在微型场景跨过真实观测校验，就停在研究原型；不直接扩大投入。
