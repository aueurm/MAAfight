# 过程观察器结算校验与暂停恢复设计

## 已确认的问题

`observeMaaBattle` 仅以三个星标区域的颜色判定结算。11-20 的战斗中，干员选中界面恰好命中该颜色规则，观察器在 `18/35` 时错误写出三星结算。另一轮在 `34/35` 停在暂停页，因没有播放恢复而无法进入最终结算。

## 目标

以完成演习为优先：观察器只在真实结果页停止；遇到暂停页时自动点击播放并继续保留过程帧。

## 最小方案

1. 保留既有星标采样，但只有同时命中左侧“行动结束 / MISSION RESULTS”固定标题区域时才承认结算。该区域在实际 11-20 结算图中亮白像素比为 20.34%，两张战斗反例分别为 2.49% 和 0%，阈值取 15%。
2. 只在顶部战斗 HUD 存在时识别画面中央 `PAUSE / 暂停中`；首次命中时保存该帧，点击右上角播放，再立即截图确认，避免干员选择界面误触。
3. 若恢复后的立即截图仍为暂停页，保留帧并继续观察；在再次看到非暂停战斗帧前不重复点击，避免干扰 Copilot 正常执行。
4. 同一“星标 + 标题”结算校验用于 `observeMaaScreen` 和 `observeMaaBattle`，避免另一条调用链保留同类误判。

## 边界

- 不加 OCR、模板库、图像依赖或 MAA 回调。
- 不改变 Copilot 选人、部署、技能或候选评分。
- 自动操作只限于暂停页的播放按钮；不启动演习，也不点击结果页。

## 验证

1. 单元测试覆盖：仅有星标的战斗帧不得结算；标题加星标才能结算；干员选择界面不得触发播放；暂停后播放恢复可继续到结算；播放后仍暂停时继续观察。
2. `npm run build:node` 和 `npm test` 通过。
3. 重新在 11-20 运行过程观察；清单不得在战斗帧提前写入 `settled`，并保留最终真实结算帧。
