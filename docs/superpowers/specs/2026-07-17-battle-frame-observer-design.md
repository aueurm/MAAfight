# 战斗过程截图观察设计

## 目标

为演习脚本保留能定位漏怪的过程证据。当前结算页观察器只能确认星数，不能判断漏怪发生前的站位、路线或技能状态。

## 范围

新增独立的 `run observe-battle` 命令，复用已有 MaaCore 截图连接：

1. 每 5 秒获取一帧 1280 × 720 PNG。
2. 帧写入 `.maafight/battle-observer/<runId>/frames/`。
3. 每帧以 Unix 毫秒命名，另写入 `manifest.json`，记录时间和文件名。
4. 识别到结算星星后立即停止，并把最终结算截图保留在同一目录。
5. 默认最多观察 10 分钟；超时保留已采集帧并明确写入 `timeout` 状态。

命令只观察，不点击屏幕、不启动战斗、不改变 Copilot 脚本，也不写入学习反馈。

## 不做的事

- 不识别右上角敌人计数：当前没有经过实际截图校准的 ROI 或可靠 OCR 证据。
- 不尝试从截图自动推断漏怪路线或修改候选评分。
- 不改动既有 `observe-screen` 的结算结果记录行为。

## 数据流

```text
已启动的演习 / Copilot
  -> run observe-battle
  -> MaaCore 截图
  -> frames/<timestamp>.png + manifest.json
  -> 人工查看漏怪前后帧
```

过程观察和既有结算观察使用同一 MaaCore 截图通道，但互不写同一结果文件。运行时连接失败、截图失败或超时均返回非成功状态，已采集帧不删除。

## 验证

1. 单元测试：帧保存、连续帧命名、检测到结算后停止、超时状态。
2. 构建与全量测试通过。
3. 在 11-20 演习中运行观察命令，确认目录中有过程帧和最终结算帧，再用这些帧分析下一次策略调整。

## 成功标准

一次未三星的演习后，用户能从同一观察目录查看漏怪前后的连续画面；系统不把未校准的图像信息当作战斗事实。
