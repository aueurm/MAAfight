# 简单关卡模型训练设计

## 目标

从约 2,000 份公共作业中筛选大量简单关卡训练 model-core，不限制公共作业使用的干员，并把训练候选从作业已使用点位扩展到地图全部合法部署点。`main_01-07` 必须完全隔离；只有新模型生成的 1-7 脚本在 MAA 演习中三星通关，任务才完成。

## 数据来源与隔离

复用 `scripts/analyze-prts-plus.js` 下载并分析约 2,000 份 PRTS Plus 公共作业。原始作业、manifest 和分析特征保存到新的数据目录，不覆盖现有 500 份快照。

所有训练入口按关卡内部 ID 排除 `main_01-07`，而不是只删除已知脚本 ID。数据集构建完成后必须同时检查 `action_samples.jsonl`、`train.jsonl` 和 `valid.jsonl`，其中不得出现 `main_01-07`。该检查失败时停止训练。

## 简单关卡筛选

仅保留地图匹配成功并满足以下条件的作业：

- `bossTypeCount == 0`
- `eliteTypeCount <= 1`
- `weightedHp <= 300000`
- `spawnCount <= 70`
- `retreatCount <= 1`

筛选不限制干员名称、星级、职业或练度。group 继续按首选真实干员解析。重复脚本 ID 只保留一份，避免多输入目录重复计权。

## 部署空间

`analyze-prts-plus` 已经计算地图全部合法部署点，但当前在写入 `features.json` 前删除了这些点。分析产物应保留精简后的 `{ row, col, buildableType }[]`。

训练的 `StageFeatures.deploymentPoints` 使用完整地图点位，公共作业实际部署点只作为正样本。负样本因此覆盖作业未使用但地图合法的格子。

候选枚举优先轮转格子，再轮转干员，确保在固定候选预算下每个合法格至少出现一次。保持现有最大候选数和依赖，不新增搜索框架；只有实测证明覆盖仍不足时才扩大预算。

## 训练与模型晋升

每轮流程固定为：

1. 下载或复用约 2,000 份公共作业。
2. 重新生成包含完整部署点的特征。
3. 筛选简单关卡并排除 `main_01-07`。
4. 构建 train / valid 数据集并执行隔离断言。
5. 训练候选模型并运行离线 eval、Jest、Python trainer test 和 model-core smoke test。
6. 用本机玩家库生成 1-7 model-core 脚本。
7. 通过 `scripts/enter-practice.ps1` 在演习模式执行并读取结算星级。

候选模型先写入独立路径。只有第 7 步确认三星，才覆盖 `models/cpu-action-ranker-latest-100.json`；失败模型保留报告但不晋升，并记录执行反馈后进入下一轮。

## 1-7 验收

1-7 使用正式关卡名生成，玩家库使用本机 `.maafight/operators.json`。执行必须走演习入口，不允许普通理智作战。

完成证据必须同时包括：

- 训练、验证和样本文件中 `main_01-07` 数量为 0。
- 生成脚本通过 ScriptValidator 和 MAAProtocolValidator。
- MAA Copilot 实际执行结束。
- 结算截图观察结果为 3 星。

协议 100 分、离线 top-k 提升、动作集合相似或 MAA 任务正常结束都不能替代三星结果。

## 失败处理

- 网络下载失败：保留已下载 corpus，重试失败项，不删除可复用数据。
- 地图无法匹配：该作业不进入简单关卡训练集。
- 1-7 无法进入演习：修复执行链路后重跑，不将其记作模型失败。
- 脚本进入战斗但未三星：记录失败反馈，分析部署序列和结算结果后再训练。
- 连续训练无改善：先检查候选覆盖、特征和数据分布，再考虑增加数据量；不引入新模型框架。

## 非目标

- 不把离线排名描述为通关率。
- 不把 1-7 作业、聚合特征或反馈动作加入训练集。
- 不新增 GPU、GBDT、神经网络或额外依赖。
- 不修改 rule-core 的选人和评分逻辑。
