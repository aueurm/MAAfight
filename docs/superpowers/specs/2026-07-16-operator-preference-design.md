# 干员选择偏好设计

## 目标

让 rule-core 优先选择用户指定的高强度干员与技能，同时保留关卡能力需求、位置匹配和完整候选评分的决定权。使用玩家干员库时，干员库只限制候选范围，不移除该强度偏好。

## 范围

只修改 `src/engine/CandidateBuilder.ts` 的可选技能集与小队 Beam Search 边际评分；不修改 `operatorCombat.v2.json` 的战斗数据，不引入配置文件或 CLI 参数。

## 规则

- 下列干员仅允许指定技能参与候选：凛御银灰 S2、忍冬 S3、怒潮凛冬 S2、赤刃明霄陈 S2/S3、司霆惊蛰 S2/S3、玛恩纳 S3、乌尔比安 S2、黍 S1、维什戴尔 S3、圣聆初雪 S2、澄闪 S2/S3、荒芜拉普兰德 S3、逻各斯 S1、艾雅法拉 S2、凯尔希·思衡托 S2、Mon3tr S2/S3、纯烬艾雅法拉 S1、遥 S2、塑心 S1、新约能天使 S2/S3、阿斯卡纶 S1、歌蕾蒂娅 S1。
- 下列干员不限制技能：斩业星熊、塞雷娅、酒神。
- 名单中的每个干员在其边际能力分数上获得固定偏置；未在名单中的干员和不符合指定技能的变体不获得偏置。
- 使用玩家干员库时，先按现有规则排除未持有或未精二的干员；在保留的干员中应用同一份技能限制与固定偏置。
- 偏置只影响 Beam Search 的候选保留顺序。位置兼容、关卡能力需求、完整候选评分和协议验证保持原样，因此名单内干员不会无条件入队。

## 名称归一化

使用战斗模型内的正式名字：`阿斯卡伦` 归一为 `阿斯卡纶`，`蕾蒂娅` 归一为 `歌蕾蒂娅`，`凯尔希思衡托` 归一为 `凯尔希·思衡托`。

## 验证

新增引擎单测：指定技能的干员只产生允许的技能变体；未指定技能的偏好干员保留全部技能；同等能力条件下，偏好干员获得更高的 Beam 排名；使用玩家干员库时，同一偏好仍生效。随后运行 `npm test -- EngineV2` 与 `npm run build:node`。
